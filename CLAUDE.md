# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A personal portfolio dashboard ("Wealth Lens"): a static, framework-free site (vanilla JS, no bundler, no build step) plus a Python price feed. UI strings are Czech-first with English alternatives; money is displayed in CZK by default.

## Commands

- `npm run dev` — runs `scripts/dev-server.py` on http://localhost:3000. It serves the static files and emulates `/api/prices`, so the app works locally exactly as on Vercel.
- Python deps (Python 3.12): `pip install yfinance pytz`.
- `python scripts/update_prices.py [--only-if-missing]` — fetches prices and appends a snapshot to `history.js`. Run from the repo root (it reads `assets.js` / `history.js` by relative path).
- There is no test suite, linter, or build.

## Architecture

**Scripts are loaded as plain `<script>` tags in a fixed order** (see the bottom of `index.html`) and share globals — there are no modules. Order matters: `version.js` → `lang/*` → `lang-init.js` (`safeStorage`) → `currency.js` → `assets.js` → `history.js` → `portfolio.js` → `calendar.js` → `ui.js` → `projector.js` → `updater.js`. A new script must be added in dependency order. `portfolio.js` announces renders via a `wl:render` custom event, which `projector.js` listens to.

**Data sources, each with one owner:**
- `assets.js` — hand-edited holdings and asset identity. It is the single source of truth: `scripts/update_prices.py` *regex-parses* it (`priceKey:` fields, `holdings: {…}`, `fixedCzk:`), so keep that formatting intact when editing.
- `history.js` — `var PRICE_HISTORY=[…]`, **generated by the updater; do not hand-edit**. Each snapshot stores rates, prices, *and the holdings at the time*, so past values aren't rewritten when holdings change.
- `api/prices.py` — Vercel serverless endpoint (`/api/prices`, via `vercel.json` rewrite) and the home of `TICKERS` / `RATE_KEYS`. The dev server and `update_prices.py` import these rather than restating them. The Yahoo symbol can differ from the asset ticker (e.g. `S.NYSE` is quoted as `S`), so adding a fund means updating both `TICKERS` and the asset's `priceKey` in `assets.js`.
- `scripts/updater.js` — client side of the live refresh (`API_URL`, timeout, toast on failure).

**Price recording pipeline** (`.github/workflows/update-prices.yml`): a primary and a backup cron run on weekdays (cron is UTC, so the Prague time shifts an hour at DST changes — see the comments in the workflow). The backup runs with `--only-if-missing` and is recognised by comparing against its cron string, so changing a cron expression means updating that comparison too. The script keeps one snapshot per Prague day (newest wins) and skips a scheduled run that wakes up on a later Prague day than its slot (`SCHEDULED_SLOT`). Missing rates, or a missing price for a *held* asset, abort the update; unheld assets are stored if available and omitted otherwise.

**Versioning:** `.github/workflows/bump-version.yml` bumps the minor version in `version.js` and `package.json` on every push to `main` (except `assets.js`-only pushes and bot commits). Don't bump it by hand, and expect `main` to move after you push — pull before further work. Price-update commits are made by `github-actions[bot]` straight to `main`.

**i18n:** strings live in `lang/lang-cs.js` and `lang/lang-en.js` (exposed as `LANG`); add keys to both.
